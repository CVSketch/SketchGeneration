## 摘要

素描是把想法外化成最简单形态的工具，探索快、沟通面也广。人工系统在内容创作和人机交互上进步很大，但要抓住人手素描那种流动、抽象的气质仍然很难。本文提出 SketchAgent：一种 **语言驱动、顺序生成** 的素描方法，用户可以通过对话式交互 **创建、修改、细化** 草图。

**本方法不需要训练或微调。** 作者利用现成多模态大模型的 **顺序输出能力** 和 **丰富先验**，通过上下文示例教模型一种直观的「素描语言」，让模型用 **字符串动作** 来「画」；程序再把这些动作变成 [[矢量图]] 并栅格化到像素画布上，画布可再次送入模型做后续任务。一笔接一笔地画，更接近素描随过程演变的特点。

实验表明：SketchAgent 能根据多样文本生成草图、在对话里改图、并与人类 **有意义地协作**。这是 **首次** 在不额外训练的前提下，用预训练多模态大模型做 **顺序素描** 的工作之一。

## 1 引言

素描能把想法压到最简形式；它 spontaneous、好改，设计师探索造型、科学家整理问题、儿童表达与学习都会用到（Fig. 2）。人工系统本可以配合这种探索式创作，但传统路线各有短板。

**数据驱动路线** 依赖人手素描数据集训练生成模型。QuickDraw 虽有约五千万笔迹，却只有 **345** 类，且多是简单图标式画法，风格与抽象程度被数据锁死，难覆盖真实世界的多样素描。

**预训练视觉—语言模型路线** 用 [[CLIP]]、文生图扩散等先验，配合可微渲染，优化参数化曲线（如 [[DiffSketcher]]、SVGDreamer），可超出固定类别。但这些方法 **同时优化全部笔画**，中间步骤 **没有笔序语义**，不能把一张图拆成反映作画过程的连贯笔画序列；而且 **每张要几分钟到一小时**，不适合实时与人轮流加笔。

本文提出 **SketchAgent**：利用多模态大模型的先验与 **逐 token 顺序生成**，做 **渐进式、语言驱动** 的素描。可从动物到工程概念等广泛文本出图（Fig. 1 左）；顺序性支持 **人机共画** 和 **聊天式改图**（Fig. 1 右）。

与直接文生图的扩散模型不同，多模态大模型吃文本（和图像），但 **只输出文本**。要出图，要么调外部工具（如文生图模型），要么让模型写 Python、SVG 等可执行代码。后者直接当素描时，形状 **太匀、太准**，缺少人手的不规则与随手感（Fig. 3B）；空间推理也弱，改图更难。

**应对方式：** 定义网格画布上的 **素描语言**，让冻住的模型输出字符串动作，**无需训练或微调**。画布是 **带编号的格子**（如 `x2y8`），增强空间指代；草图是 **有语义顺序的笔画序列**，每笔画一串格点坐标。用 **上下文学习（ICL）** 教格式，用 **思维链（CoT）** 做规划；坐标序列经 **贝塞尔拟合** 再渲染，外观更自然。协作时画布对人、对 agent 全程可见；模型顺序出笔，在可调 **停止符** 处暂停，用户可插笔，插笔再转回 agent 格式继续画。

## 2 相关工作

### 素描生成

早期用图像滤波模拟素描感。深度学习出现后，出现类别条件素描、物体/场景素描、补全、肖像、部件级生成等任务。素描数据采集难，风格与任务差异大，难用单一数据集包全。QuickDraw 最大，但类别与 iconic 程度仍限制数据驱动方法。

大规模预训练视觉—语言模型（文生图扩散等）可 prompted 出「像素描的图」，但是 **单步像素图**，没有人手那种 **逐笔过程**。后续工作用扩散等先验 **迭代优化** 参数曲线 + 可微光栅化，减轻对人手数据的依赖，但 **全笔画一起优化** 仍缺时间与语义结构，且耗时长，不适合协作素描。

### 多模态大模型与内容创作

大模型与多模态大模型以文本（及图像）为输入、文本为输出。要出视觉内容，常配外部工具（如 ChatGPT 调 DALL·E 3），或生成 Python、SVG、TikZ 等再渲染。这类 **代码出图** 往往 rigid、几何形状过准，缺少自由素描的 subtle irregularities（Fig. 3B）。本文用 ** grounded 在空间信息上的素描语言**，鼓励更自然的素描外观，再后处理成 [[矢量图]]。增强手段包括 CoT、ICL 等。

### 顺序画与协作素描

人机协作素描在 HCI、图形学、机器人、认知与学习科学里都有探索；核心是 **顺序、自适应、每笔有意图**。已有方法用 RL、对抗、referential game、Transformer 等学离散笔画序列；SketchRNN 用 QuickDraw 训 RNN，也被用于协作，但 **类别仍限于训练集**。

## 3 预备知识

### 矢量图与贝塞尔曲线

[[矢量图]] 由点、线、曲线、多边形等几何基元直接描述，与像素栅格图不同：可缩放、紧凑、可编辑。SVG 是常用的 XML 矢量格式。栅格化指把矢量渲成像素图。

三次贝塞尔曲线（Fig. 4）由起点 $P_0$、终点 $P_3$ 和两个控制点 $P_1,P_2$ 定义，控制点集 $P=\{P_0,P_1,P_2,P_3\}$：

$$
B(t) = (1-t)^3 P_0 + 3(1-t)^2 t P_1 + 3(1-t)t^2 P_2 + t^3 P_3,\quad t\in[0,1].
$$

$t=0$ 在 $P_0$，$t=1$ 在 $P_3$；曲线上采样点一般 **不在** 控制点上，因此不宜直接把格点当控制点。

## 4 方法

目标：让 **现成预训练多模态大模型** 按自然语言指令画素描（Fig. 5 总览）。使用 **冻住** 的多模态 LLM（文中称 SketchAgent），输入三块：(1) **系统提示**，教网格与素描语言；(2) **用户提示**，具体任务（如「画一条鲨鱼」）；(3) **空白编号画布**。模型输出文本形式的 **笔画序列**，程序拟合贝塞尔、渲染；画布可 **带着新用户提示再喂回模型** 做改图，或 **让人直接在画布上画** 做协作。

### 画布

多模态模型推理强，但 **细粒度空间推理** 常弱（Fig. 6：GPT-4o 能说出要连点 1 和 5，却用像素 `draw line` 连不对）。因此用 **编号网格**：横、纵轴各标 **1 到 50**，左下角格为 `x1y1`。模型用 `(x,y)` 格名指位置。

### 草图表示

草图是 **有序笔画** $S=\{S_1,\ldots,S_n\}$。第 $i$ 笔 $S_i=\{(x_j,y_j)\}_{j=1}^m$，文本里写成 `<points>x1y1, x15y20, ...</points>`。

**后处理三种思路（Fig. 7）：**

1. **折线**：格点稀，折、硬。
2. **格点当贝塞尔控制点**：控制点不在曲线上，模型难反推。
3. **本文**：格点为曲线上的 **采样点**，并给出每个点的参数 $t_j\in[0,1]$，用最小二乘拟合三次贝塞尔：

$$
P = \arg\min_P \|AP - B\|,
$$

$A\in\mathbb{R}^{m\times 4}$ 为各 $t_j$ 上的三次基函数值，$B\in\mathbb{R}^{m\times 2}$ 为采样点。拟合误差大则 **递归切分**；也支持二次、直线、点。最后把参数曲线渲染到画布。

### 绘制指令

**系统提示** 固定：声明「专家素描画师」、介绍网格与 **单笔图元** 示例（附录 Fig. 15，**不是失败样**）。**用户提示** 含任务描述，以及 **一整座小房子的完整 ICL 示例**（附录 Fig. 16）；作者强调 **没有这座完整例子时，格式常乱到无法解析**。

模型按 Fig. 5 灰框格式回答：在 `<thinking>` 里规划部件、顺序、布局（CoT）；每笔后跟 `<id>` 语义标签（如 dorsal fin），便于分析与大规模标注。

### 4.1 聊天改图与人机协作素描

迭代流程支持多轮任务。**聊天改图**：把 **渲染后的画布** 与用户新指令一起送回模型（Fig. 5 虚线箭头），更新用户提示即可。

**协作**：画布对人、对 agent 全程开放。停止符 `</s{j}>` 让模型在第 $j$ 笔后暂停；已生成笔画先处理并显示，用户再画。用户笔画通过 **反拟合**：沿贝塞尔多 $t$ 采样，取 **最近格心**，转成与 agent 相同格式， **接在 agent 序列后**，agent 继续画到下一停止符。

## 5 结果

正文实验默认骨干为 **Claude 3.5 Sonnet**（20240620），除非另说明。更多任务与图见附录。

### 5.1 文本条件素描生成

Fig. 1、Fig. 8 展示超出常规范畴的概念：科学概念（双缝、摆）、示意图（电路、流程图）、地标（泰姬陵、埃菲尔铁塔）等。

**定量：** 从 QuickDraw **345 类中随机抽 50 类**，每类用本文方法生成 **10** 张，共 **500** 张。用 [[CLIP]] 零样本分类器（与 DiffSketcher 等惯例一致）看是否像该类。对比骨干：GPT-4o-mini、GPT-4o、Claude 3 Opus、Claude 3.5 Sonnet；基线含 QuickDraw 人手样本。

**表 1：素描识别（500 张、50 类，CLIP 平均 Top-1 / Top-5）**

| 方法 | Top-1 | Top-5 |
| :--- | :--- | :--- |
| GPT-4o | $0.15\pm 0.04$ | $0.30\pm 0.06$ |
| GPT-4o-mini | $0.04\pm 0.03$ | $0.10\pm 0.04$ |
| Claude 3 Opus | $0.13\pm 0.04$ | $0.27\pm 0.05$ |
| Claude 3.5 Sonnet（本文默认） | $0.23\pm 0.04$ | $0.44\pm 0.03$ |
| Claude 3.5 Sonnet 直接写 SVG* | $0.23$ | $0.43$ |
| 人手 QuickDraw | $0.27\pm 0.07$ | $0.49\pm 0.06$ |

*提示：「Write SVG string that draws a sketch of a \<concept\>. Use only black and white colors」。

人手 Top-1 最高；Claude 3.5 Sonnet 在模型里最好，接近人手 CLIP 分。直接 SVG 的 CLIP 与本文接近，但形状 **更匀、更准**，缺自由素描的 fluidity（Fig. 3）。

**2AFC「像不像人手」：** **150** 名被试，**50** 类每类 **1** 张，共 **150** 张/方法；两选一哪张更像人手画的。本文 vs 直接 SVG：本文被选为「人手」的比例 **$74.90\pm 3.35\%$**；本文 vs 人手：略偏人手 **$54.68\pm 4.61\%$**；直接 SVG vs 人手仅 **$38.9\pm 5.55\%$**。

Fig. 9：逐笔生成，右侧为 agent 给的语义与顺序标签。

### 5.2 顺序素描

Fig. 10 对比 **SVGDreamer**（约 **2000** 步、**1.6 小时**）：中间步与单笔画 **缺清晰语义**；最终图因扩散骨干可以很细，但不适合交互。**SketchRNN**（约 **4 秒**）：真顺序、实时，但 **限 345 类**。**本文**（约 **20 秒** 一张）：渐进出笔、每笔有语义，且概念不限于训练类。**人手** QuickDraw 也是渐进的。

Fig. 11 左：QuickDraw 笔画数多集中在 1–6，本文分布更宽，峰在 5–10，说明 QuickDraw 平均 **更抽象**。右：在 **4–7 笔** 子集（本文 204 张、QD 120 张）上，随笔画累积 CLIP 分 **都上升**，模式相近。

### 5.3 人机协作素描

Web 环境（附录 Fig. 40–41）：**400×400** 共享画布；**solo** 用户独立画，**collab** 与 agent **轮流一笔**。参照 collabdraw，选 agent **能单独画好** 的 **8** 个简单概念；**30** 人（32 人回收、2 人未完成剔除），每概念 solo + collab，共 **480** 张。用户与 agent 谁先手 **15/15 平衡**。

Fig. 12B：协作整图（蓝）识别率 **接近仅用户**（绿虚线）， **高于仅 agent**（粉虚线）。只保留 **agent 笔** 或 **用户笔** 的局部图，识别率 **明显下降**，说明双方都对最终可辨度有贡献。平均笔画数：协作整图 **7.333**，solo agent **7.321**，solo 用户 **7.708**，复杂度相当。

### 5.4 基于聊天的素描编辑

输入为 **文本 + 图像**。三类各 3 个物体、各 3 条编辑口令：**户外 / 室内** 指定相对位置（如 left to、on top of）；**动物** 只给「加眼镜 / 帽子 / 裙子」，测语义推断位置。共 **54** 张编辑结果（Fig. 13）。

指令遵循：**92%** 总体正确；**指明相对关系** 时 **94%**；**纯语义推断**（如帽子在头上）**88%**。

## 6 消融

在 5.1 协议上 **逐项去掉** 组件，测 CLIP 识别（500 张、50 类）。

**表 2：消融（平均 Top-1 / Top-5）**

| 设置 | Top-1 | Top-5 |
| :--- | :--- | :--- |
| 去掉系统提示 | $0.20\pm 0.04$ | $0.42\pm 0.03$ |
| 去掉 CoT（无 thinking / step-by-step） | $0.14\pm 0.02$ | $0.29\pm 0.04$ |
| 改 ICL（仅单笔格式例，无整图房子） | $0.07\pm 0.02$ | $0.16\pm 0.03$ |
| 完整 SketchAgent | $0.23\pm 0.04$ | $0.43\pm 0.06$ |

完全去掉 ICL 会导致 **格式无法解析**；用单笔例代替完整房子例，性能 **大跌**。附录 C 有可视化：CoT 与 **房子 ICL 示例** 对质量都很关键；ICL 主题（猫 vs 房子）会牵动外观，复杂猫例甚至 **过拟合** 示例形状（Fig. 49–50）。

## 7 局限与未来工作

![[图/SketchAgent/fig14.png]]

图 14：**正文局限与失败样**（附录 Fig. 15 是系统提示里的 **单笔图元**，不是失败样）。(A) 复杂概念过抽象、认不出；(B) 人物过简；(C) 字母、数字画不好。

**骨干先验：** 模型主要为 **文本** 优化，不是为视觉落笔优化。agent 常能 **用文字细写部件**，却 **转不成有效笔画**，输出 **过抽象、不可辨**。Fig. 14A：独角兽的角等在文字里清楚，图认不出；Fig. 14B：弗里达眉、乔丹扣篮等 **语言能抓住**，成图却是 **过于简单、业余（amateur）风**，缺表现力——整体接近 **儿童简笔**，不是专业课堂素描的调子与阶段。

**字母与数字** 弱（Fig. 14C，如可口可乐字标、勾股定理式子）；作者认为未来模型视觉变强、并补 ICL 示例可能改善。

**方法边界（读文时要划线）：** 全文 **不训练、不微调**，能力来自冻住多模态 LLM + 网格语言 + 系统/用户提示与 ICL。附录 B.1 写明：**方法主要在 Claude 3.5 Sonnet 上开发，所用提示词也按该模型优化**；换骨干往往还要 **额外 prompt engineering**。若后继工作止步于「再换提示词、换接口、加一轮对话」，而不解决 **可辨度、调子、课堂式阶段**，很容易被审稿人与同行看成 **「又一个聊天画手」**——与第 7 节自承的 amateur 风格是同一问题的两面。

作者期待更强视觉模型与更丰富的素描语言，走向 **通用、可迭代交互** 的人工素描系统。

## 8 结论

本文给出 **语言驱动、顺序** 的素描生成：实时出图、可与人 **有意义协作**。预训练多模态 LLM 的先验可通过 **直观素描语言 + 网格画布** 用于素描，**无需额外训练或微调**，向 **通用人机视觉沟通与计算机辅助构思** 迈一步。

#### B.1 文本条件定量补充

5.1 之外，另设三类 **需通识** 的概念，各用 ChatGPT-4o 抽 **10** 个随机词，每词生成 **5** 张（每类 50 张）：

- **科学概念：** 双缝、摆、光合作用、DNA 复制、牛顿定律、电磁波谱、板块、量子纠缠、有丝分裂、黑洞形成等。
- **示意图：** 电路、流程图、组织图、ER 图、维恩图、思维导图、甘特图、网络拓扑、饼图、决策树等。
- **地标：** 泰姬陵、埃菲尔铁塔、长城、吉萨金字塔、自由女神、斗兽场、悉尼歌剧院、大本钟、富士山、马丘比丘等。

Fig. 18–20 展示结果：多数能表达概念且多样；也有失败个例（如自由女神、光合作用、饼图等）。

**500 张 CLIP 混淆（Fig. 21–23）：** 常见混淆如 shark→fish、octopus→spider、snake→squiggle 等，多发生在 **相近类**；风格 ** inherently abstract** 难强调判别特征。fish 类 **10/10** 全对；house、umbrella、table **9/10**。

**换骨干（Fig. 24–25）：** GPT-4o 最好 house/eye；Claude 3.5 Sonnet 最好 umbrella/bus；最差类含 snake、octopus、shark、watermelon 等，与 Table 1 一致。GPT-4o 与 Claude 3.5 Sonnet 整体最好；**画风因骨干而异**。附录写明：**提示按 Claude 3.5 Sonnet 优化**，其他模型或可再调 prompt，留作 future work。

**开源骨干：** Llama-3.2-11B-Vision 常 **复读用户提示里的房子 ICL**（Fig. 26），几乎无意义。**Llama-3.1-405B-Instruct** 可泛化，500 张 CLIP Top-1 **$0.052\pm 0.03$**、Top-5 **$0.1\pm 0.03$**（Fig. 27–28），低于商业模型但 **视觉连贯**，说明公开模型也可用，性能有折中。

**直接 SVG（Fig. 29）：** 对 giraffe、lighthouse 等，各骨干直接写 SVG / sketch-like SVG，多为 **匀整几何**（椭圆、三角），与手绘 expressiveness 不符；GPT-4o 与 Claude 3.5 的 SVG 相对更「好看」，与生成质量差异一致。

**2AFC 细节（Fig. 30–31）：** Amazon Mechanical Turk **150** 工人，每人 **50** 次对比；筛选 approval **≥99.9%** 且 **>1000** 调查记录；完成全程酬 **\$0.5**。
